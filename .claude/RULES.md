# 项目开发规则

本文档记录了在本项目开发过程中需要遵循的核心规则和原则。

## 1. 系统化规划与实施

### 规划阶段
- 在实际编程前必须列出完整的功能清单和todo列表
- 明确每个功能模块的职责和接口
- 制定详细的实施步骤

### 实施阶段
- 对每一项功能单独编程实现
- 确保每个模块独立可测试
- 最后整合为完整方案
- **核心原则：尽量一次成型，避免多次修改代码**

## 2. 谨慎求证原则

### 技术不确定性处理
- 遇到不懂或不确定的技术问题时，**绝不凭直觉猜测**
- 主动进行网络搜索验证技术细节
- 查阅官方文档和最佳实践
- 如果搜索后仍不清晰，**直接向用户询问**

### 信息验证流程
1. 识别不确定点
2. 网络搜索验证
3. 文档查阅确认
4. 必要时询问用户

## 3. 质量与沟通优先

### 代码质量要求
- 确保代码的**健壮性**：处理异常情况，避免崩溃
- 确保代码的**可维护性**：清晰的结构，合理的命名，适当的注释
- 遵循项目既有的代码风格和架构模式

### 主动沟通原则
- 如果用户需求有**不合理**的地方，提前告知
- 如果用户需求**难以实现**，提前说明
- 主动提出**替代方案**和**优化建议**
- 在实施前确认理解用户真实意图

## 应用指导

这些规则的目的是：
- 提高开发效率，减少返工
- 确保代码质量和项目稳定性
- 促进有效沟通，避免误解
- 建立可持续的开发流程

在每次开发任务开始前，请回顾这些规则，确保严格遵循。
